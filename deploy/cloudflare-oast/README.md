# AOBTD HTTP OAST prototype

> **Status:** parked, opt-in prototype. It is not required for normal AOBTD
> operation and is not intended to be a shared multi-tenant service.

This Cloudflare Worker records signed HTTP callbacks generated by AOBTD SSRF
probes and exposes them through an authenticated polling API. When OAST is not
configured, AOBTD continues to run and keeps SSRF-shaped observations at
`possible` confidence instead of claiming callback confirmation.

Each operator must self-host this service and generate their own credentials.
Do not distribute the credentials for `oast.aobtd.com`, put them in a committed
file, or include them in an application binary.

## Security model and current limits

- Probe IDs are random and HMAC-signed.
- Polling requires a bearer token.
- Callback request bodies and sensitive headers such as `Authorization` are
  not stored. Events expire after 24 hours.
- The two credentials are operator-wide secrets. There is no user isolation,
  registration flow, rate-limit policy, or short-lived credential issuer yet.
- Only HTTP/HTTPS callbacks are supported. DNS-only OAST requires a separate
  authoritative DNS service.

Because the credentials are operator-wide, this prototype is suitable for one
trusted operator or an isolated internal deployment—not a public hosted service.

## Self-host on Cloudflare

Prerequisites are a Cloudflare account, a domain managed by that account,
Node.js/npm, and Wrangler authentication.

1. Install the Worker dependencies and authenticate:

   ```sh
   cd deploy/cloudflare-oast
   npm ci
   npx wrangler login
   ```

2. Create a D1 database:

   ```sh
   npx wrangler d1 create aobtd-oast
   ```

3. In `wrangler.toml`, replace `database_id` with the returned ID. Replace the
   `routes.pattern` value with a hostname under your own Cloudflare-managed
   domain, for example `oast.security.example`.

4. Apply the schema and deploy the Worker once:

   ```sh
   npx wrangler d1 migrations apply aobtd-oast --remote
   npx wrangler deploy
   ```

5. Configure two independent 32-byte secrets:

   - `AOBTD_OAST_SIGNING_KEY` signs probe IDs.
   - `AOBTD_OAST_API_TOKEN` authenticates event polling.

   On macOS, the included helper generates both values, uploads them through
   Wrangler without printing them, and stores matching copies in Keychain:

   ```sh
   npm run secrets:configure
   ```

   On other operating systems, generate both values in a password manager or
   OS secret store, then enter each one interactively with:

   ```sh
   npx wrangler secret put AOBTD_OAST_SIGNING_KEY
   npx wrangler secret put AOBTD_OAST_API_TOKEN
   ```

   The scanner must receive the same values through its process environment.
   Never save them in `.env`, `.dev.vars`, `wrangler.toml`, shell history, test
   fixtures, issues, CI logs, or screenshots.

6. On macOS, load the Keychain values before starting AOBTD. Override the base
   URL when using a hostname other than the prototype default:

   ```zsh
   export AOBTD_OAST_BASE_URL="https://oast.security.example"
   source deploy/cloudflare-oast/load-aobtd-env.zsh
   ```

   Other platforms must set all three values using their process supervisor or
   secret manager:

   ```text
   AOBTD_OAST_BASE_URL=https://oast.security.example
   AOBTD_OAST_API_TOKEN=<from-your-secret-store>
   AOBTD_OAST_SIGNING_KEY=<from-your-secret-store>
   ```

7. Verify the public callback and authenticated polling path. The bundled smoke
   test currently loads credentials from macOS Keychain:

   ```sh
   AOBTD_OAST_BASE_URL="https://oast.security.example" npm run smoke
   ```

## Repository safety

`.env`, `.dev.vars`, `.wrangler/`, and Worker dependencies are ignored. The
committed Worker configuration contains only resource identifiers and routing
metadata; Cloudflare secret values and local Keychain values must remain outside
the repository. Before publishing changes, compare staged content against your
secret store and run a dedicated secret scanner when available.

A future shared service should replace the operator-wide credentials with
authenticated, scoped, short-lived per-user or per-scan credentials before this
prototype is enabled by default.
